# Class Quiz Arena 개선 구현 계획

- 작성일: 2026-09-26
- 기준: `work/elementary-webapp-ux-audit.md`의 현재 로컬 소스 감사
- 범위: 승인된 구현과 로컬 검증. 커밋·푸시·배포·HVC 등록은 포함하지 않는다.
- 역할: 기획·조율·리뷰는 주 에이전트, 코드 구현은 `gpt-6-luna` 서브에이전트.

## 완료 목표

1. 학급·방·문제·사용자 데이터의 읽기/쓰기 권한을 역할과 소속으로 제한하고, AI 문제 생성 호출은 담당 교사만 허용한다 (`SEC-01/02`). 클라이언트가 점수·승자·보상을 임의 확정하지 못하도록 상태 전이를 검증한다.
2. 초대 코드 실패, 새로고침, 네트워크 오류에서도 학생이 현재 상태와 다음 행동을 알 수 있다 (`FLOW-01/02`, `AUTH-01`, `UX-01`). 학급 ID가 없을 때 다른 학급 콘텐츠는 표시하지 않는다.
3. 첫 답만 확정하고 양쪽 제출 또는 시간 종료 전에는 정답을 공개하지 않는다. Firestore `Timestamp`를 정확히 처리한다 (`GAME-01/02`).
4. 해설과 오답 복습을 결과 흐름에 연결하고, 문제별 통계의 키와 분모를 정확히 계산한다 (`LEARN-01`, `DATA-01/02`). 문제 수와 준비 상태의 문구는 실제 데이터와 일치시킨다 (`LANG-01`).
5. 320/375/1280px의 카드·교사 작업 화면, 로그인 제목, 모달 포커스를 개선한다 (`UX-02`, `ACCESS-01`, `UI-01`). 500줄 이상 파일을 기능 단위로 분리하고 필요 없는 초기 로드를 줄인다 (`CODE-01`).

## 구현 순서와 담당 파일

### A. 서버와 대전 무결성 — Luna 서버 담당

- 소유: `firestore.rules`, `functions/src/**`, `src/lib/battle.ts`, `src/hooks/useRoom.ts`, `src/hooks/useMatch.ts`, `src/lib/award.ts` 및 그 직접 테스트.
- 기존 클라이언트 API를 최대한 유지한다. 변경이 필요하면 학생 담당에게 먼저 계약을 전달한다.
- Rules와 Functions의 허용 조건을 같은 데이터 구조에 맞춘다. 새 서버 함수가 필요한 경우 함수 단위의 역할 검사·입력 검증·중복 호출 방어를 포함한다.
- 배포되지 않은 로컬 규칙을 운영 반영으로 표현하지 않는다. 에뮬레이터가 없다면 단위 테스트와 코드 검증을 하고 에뮬레이터 검증을 미실행으로 남긴다.

### B. 학생 진입·학습 흐름 — Luna 학생 담당

- 소유: `src/App.tsx`, `src/pages/BattleRoom.tsx`, `src/pages/StudentHome.tsx`, `src/pages/ClassJoin.tsx`, `src/pages/LoginScreen.tsx`, `src/components/Modal.tsx`, `src/hooks/useClassroom.ts`, `src/hooks/useArenas.ts`, `src/hooks/useProfile.ts` 및 그 직접 테스트.
- 서버 담당이 바꾸는 방 상태 API와 맞춰 답 잠금·정답 공개 시점·재진입을 구현한다. 학생에게 보이는 해설·오답 복습은 정답 노출 경계를 지킨다.
- App의 역할별 셸을 분리해 500줄 규칙을 지킨다. 모바일에서 주요 카드와 버튼이 읽히도록 한다.

### C. 교사 화면·분석 — Luna 교사 담당

- 소유: `src/pages/TeacherHome.tsx`, `src/hooks/useTeacherRooms.ts`, `src/hooks/useAnalytics.ts`, `src/lib/analytics.ts`, `src/index.css`, 과목별 SVG 분할 파일 및 그 직접 테스트.
- 교사 방 목록은 교사 소속 학급으로 제한한다. App에서 학급 ID 인수가 필요하면 학생 담당과 인터페이스를 조율한다.
- 문제별 응답자 수를 분모로 계산하고, 정답률 미기록은 0%와 구별한다. 교사 화면의 500줄 이상 파일과 과도하게 긴 SVG 파일을 분리한다.

### D. 통합 — Luna 통합 담당

- 세 작업의 타입·규칙·테스트를 맞추고 `docs/UPDATELOG.md`와 `src/data/updatelog.ts`에 같은 날짜·문구를 최신순으로 기록한다. 업데이트 내역에는 관리자 모드 내용을 쓰지 않는다.
- `src/data/updatelog.test.ts` 포함 전체 테스트, 웹 빌드, 함수 빌드를 실행한다. 구현과 검증에 필요한 후속 코드 수정을 담당한다.

## 공통 계약

- 서로 다른 담당 파일을 동시에 수정한다. 공유 타입이나 컴포넌트 변경은 메시지로 조율한다.
- 정답이 든 기존 문제 문서는 교사용으로 유지한다. 대결 참가자는 서버 함수로 정답을 뺀 문제만 받고, 제출 답은 라운드 확정 전 서버 전용 문서에 둔다. 따라서 기존 문제 데이터 이관은 필요하지 않다.
- 교사가 다른 반의 공개 아레나를 가져오는 기존 은행 기능은 교사 권한으로 보존한다. 학생은 타 반 문제와 정답을 읽지 못한다.
- 보상을 서버에서 확정하면 기존 별 상점 구매도 서버에서 상품 ID·가격을 검증하도록 연결한다.
- 학생 화면은 초3–4를 기본으로 짧고 구체적인 한국어를 사용하고, 핵심 교과 용어는 보존한다.
- 학습 단계의 핵심 버튼은 기존 `gi-pulse` 강조와 `prefers-reduced-motion` 대체를 유지한다. VoiceOver 구현·검증은 범위에서 제외한다.
- 기존 SVG와 사진 필요성 평가 결과에 따라 이번 수정에서 새 장식 이미지는 만들지 않는다. 시뮬레이션은 학습 목표에 불필요하다는 기존 결정에 따른다.
- 새 의존성 설치 없이 현재 환경에서 구현한다. 변경된 코드만이 아니라 동일 실패 시나리오를 테스트한다.
