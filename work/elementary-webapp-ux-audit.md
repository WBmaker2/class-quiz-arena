## 학생 패널과 화면 검토

- **cold start 관찰:** 로그인 화면에서 보이는 다음 행동은 `Google 계정으로 시작하기` 하나이며, 버튼의 52px 높이·Tab 포커스·320/375/1280px 가로 넘침 없음은 확인됐다. DOM 제목은 없다.
- **준호(초3–4) 관점의 재진술:** `Google 계정으로 들어가 친구와 퀴즈를 한다`까지는 보이는 단서로 설명 가능하다. 학급 입장, 첫 오답, 완료 뒤 다음 행동은 인증된 실제 경로를 따라가지 못해 판정하지 않는다.
- **민서(초1–2) 가드레일:** 로그인 문장은 짧지만 `아레나`, `XP`, 정답률처럼 이후 노출되는 추상어는 풀이가 필요하다. 이는 소스 문구 점검이며 실제 저학년 반응이 아니다.
- **서윤(초5–6) 가드레일:** `왜 틀렸는가`와 기록의 근거가 부족할 가능성이 높다. 해설 저장/학생 미표시와 정답률 미갱신으로 판단한 소스 근거다.
- **시각 가독성:** 로그인 화면의 버튼 크기와 폭은 확인. 인증 후 학생 2열 카드·교사 편집기·모달의 실제 배치/대비 점수는 보류.
- **디자인 방향:** 크림색 바탕·남색 주요 버튼·종이 카드·자체 SVG의 일관성, 반복 CTA의 펄스와 `prefers-reduced-motion` 대체는 소스에서 확인된다(`src/index.css:3-17,101-156`). 로그인 화면에서는 중요한 버튼 하나가 분명했다. 인증 뒤의 카드 밀도와 그림의 실제 시선 흐름은 캡처 실패 때문에 시각 판정을 보류한다.
- **언어 가독성:** 상태별 장부는 [문구 감사](elementary-webapp-ux-language-audit.md). 문구 변경 후 동일 상태의 이해 probe가 필요.

## 개선 순서와 수용 기준

1. **권한·데이터 경계:** SEC-01/02. 실제 운영 반영 전 에뮬레이터 다중 역할 거부 테스트와 배포 규칙 확인.
2. **핵심 흐름·공정성:** FLOW-01/02, GAME-01/02. 잘못된 초대 코드, 한 번 답하기, 30초 경계, 새로고침 복원을 같은 시나리오로 검증.
3. **교육적 피드백·통계:** LEARN-01, DATA-01/02, LANG-01. 교사 해설 검토 → 오답 회복 → 복습/다음 행동과 수치 분모 일치.
4. **화면·코드 구조:** UX-01/02, ACCESS-01, CODE-01. 인증된 세 viewport·키보드·네트워크 오류 점검, 번들/로딩 측정.

100점 수용 점수는 로그인 뒤 핵심 흐름의 실제 브라우저 증거가 없으므로 **미산정**이다. 현재 로컬 소스에는 P0/P1이 남아 있어 필수 게이트는 `fail`; 운영 서비스에 동일 규칙이 배포됐는지는 `not run`이다. 수정 전후 점수 비교와 동일 시나리오 재검증은 이번 `audit-only`에서 해당하지 않는다.
